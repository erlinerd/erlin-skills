# 目标

把苹果设计品味落到移动端引导页（onboarding / first-run / welcome）的方法论。核心教训：引导页做成"两张错位卡 + 中央色块装图标"，首屏会与其他页同构、读起来像模板；每页应是一张"旅程轴进主卡"的迷你场景，不动一个字的文案。

# 执行步骤

1. **先盘点，再动手**：读流程结构（几步、每步 kicker/title/subtitle/example 文案、final 动作如请求通知权限落在哪步）；读本地化（全部沿用已有 `LocalizedStringKey`，不新写文案）；读 UI 测试对引导页的契约（跳过引导靠哪个按钮 label、权限流）——视觉随便改，契约别碰；读设计系统 token（颜色/圆角/字体/动效常量），全程用 token，别发明新值。
2. **插画做成"产品的迷你场景"（Familiarity + Craft）**：抽象图标（icon 进色块）→ 用产品自己的视觉语言搭的微型场景：用户明天会看到的卡片形态 + 一条承载概念的"轴/线"。**一个统一场景，按步骤参数化**：只换轴上的标记（起点 / 断点 / 等待点 / 提醒 chip）、tint 色、一个小细节。统一构图 = 成体系的系统，不是四张各自为政的插画。例：统一场景是"旅程轴进入一张 Matter 卡"——重归步只靠琥珀 + 反转墨块断点就讲清"跳回断点"，通知步靠右上角珊瑚角标 chip 讲"提醒到你面前"。模板见 `assets/vignette.swift`（通用版"旅程轴进主卡"插画组件，参数化后可套任意宿主）。
3. **装饰零文案**：全部形状 + 通用 SF Symbol，绝不硬编码语言。本地化 App 里这直接消灭一整个麻烦。
4. **首屏给真正的 hero**：display 档大标题（30–34pt、紧 leading、负 tracking；**CJK 别加 tracking**）；`lineLimit(2)` + `minimumScaleFactor` 防截断；后续页用常规标题，形成首屏"宣言"、后续"说明"的落差。
5. **动效有叙事顺序（Apple Fluid Interfaces）**：一次性、可打断、reduced-motion 安全（reduce 下 = 直接落定，传 `nil` animation）；单入口 flag（如 `entered`）驱动全屏入场；顺序讲故事：**标记现 → 线画下 → 卡落位 → 文字 stagger**；不加守旧循环动画：慢振荡（近 0.2Hz）既吵又对前庭危险，除非是极小声的环境光晕。
6. **克制**：不加 "跳过" 大按钮、不引入新页面 / 新流程 / 新文案；逻辑保持原样，只动视觉和动效；引导页维持"一步一个焦点"，别把概念卡堆成说明书。
7. **验证（无图也能验）**：构建 → 使用项目已有的 UI 测试或 Simulator 交互流程逐页截图 → Vision OCR 逐页确认文字完整、无截断/重叠、按钮在；逐页像素色调探针（Python/Pillow 数 palette 色像素占比）确认每页渲染了该有的色，**明暗两套各验一次**；单测跑全量；UI 测试挂了**先 A/B 再下结论**（细则见「门禁」）。

# 判断规则

**何时使用**：

- 新建或重做 App 引导页（"更新引导页" / "onboarding 太平淡" / "做个 welcome"）
- 评估一个引导页该不该重做
- 给引导页配动效、给首屏配 hero 级标题

**该重做的信号**（命中 ≥2 条就动手）：

- 插画是"图标放进色块"，跟产品本身无关
- 每页模板完全同构，只是换图标换颜色
- 首屏标题和其他页一样大，没有 hero 感
- 装饰插画里塞了硬编码文案（本地化毒药）
- 一页好几段文字堆成说明书，没有单一焦点

**纪律判断**：

- **UI 测试契约优先**：跳过引导的测试靠"开始使用/继续"这类按钮 label 活着。你改的是视觉，标签别动。
- **别发明 tone**：页面色调沿用产品语义（如"重归"页用警告琥珀），不要为了好看乱配色。
- **动效顺序要讲概念**：轴"画下来"是在暗示连续性与方向（我停住的那条线从这里继续），不是炫技。

**与相邻技能的关系**：`apple-design`（动效/字体/材质原理的上游理论）、`erlin-skill-distill`（蒸馏法本身）。

# 输出格式

- 每页 = 统一"旅程轴进主卡"迷你场景，按步骤参数化（轴标记 / tint 色 / 一个小细节），一步一个焦点。
- 首屏 display 级大字 hero（30–34pt、紧 leading、负 tracking；CJK 不加 tracking），`lineLimit(2)` + `minimumScaleFactor` 保底；后续页常规标题。
- 装饰全部形状 + 通用 SF Symbol，零硬编码文案；文案全部沿用已有 `LocalizedStringKey`；全程设计系统 token，不发明新值。
- 动效为单入口 flag 驱动的一次性入场，顺序：标记现 → 线画下 → 卡落位 → 文字 stagger；reduced-motion 下直接落定（`nil` animation）。

# 示例

## 用户问题

"引导页太平淡了，更新一下，要有 Apple 那种品味。"

## 工具返回

### 现有引导页盘点（实际输入材料）

3 步流程（每步 kicker/title/subtitle/example），final 动作（请求通知权限）在第 3 步；文案全部是已有 `LocalizedStringKey`；UI 测试靠"继续"按钮 label 跳过引导；设计 token 含颜色/圆角/字体/动效常量。重做信号命中："图标放进色块"与产品无关 + 每页同构 + 首屏无 hero——≥2 条，动手重做。

### Vision OCR（项目脚本，验证阶段返回）

逐页截图 OCR：文字完整、无截断/重叠、按钮在；明暗两套各扫一次。

### Pillow 像素探针（验证阶段返回）

逐页 palette 色像素占比：重归页出现警告琥珀、通知页出现珊瑚色，每页该有的色都渲染了。

## 最终输出

- 重做后的引导页：统一"旅程轴进主卡"场景按步骤参数化——重归步靠琥珀 + 反转墨块断点讲"跳回断点"，通知步靠右上角珊瑚角标 chip 讲"提醒到你面前"；首屏 display 级 hero 大字；动效按"标记现 → 线画下 → 卡落位 → 文字 stagger"入场；文案零改动、逻辑零改动。
- 验证证据：明暗两套 OCR 与像素探针通过、全量单测通过、UI 测试差异已 A/B 归因。

# 门禁

- **验证完才许报完成**：构建通过；逐页截图 Vision OCR 确认文字完整、无截断/重叠、按钮在；逐页像素色调探针明暗两套各验一次；单测跑全量。
- **OCR 工具纪律**：OCR 工具必须来自项目脚本、技能 `assets/`，或当前机器已安装且先通过命令探测；不要依赖临时路径或未声明的 GUI 点击工具。缺少可执行 OCR 时明确记录"待执行 OCR"，不得报告为已验证。
- **UI 测试失败先 A/B 再下结论**：把改动 stash 掉、还原成原代码跑同批测试；若原代码也挂，就是环境/既有问题，别赖自己（4 条 UI 测试改动前后同样失败，全是既有环境问题）。
- **不动红线**：不碰 UI 测试契约的按钮 label；不新写文案、不引入新页面/新流程；逻辑保持原样，只动视觉和动效。
