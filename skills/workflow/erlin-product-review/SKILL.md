# 目标

**多视角产品评估。**对产品/功能/版本/落地页/PR 从四个视角做证据驱动的评估。输出：四张视角评估卡 + 一张按优先级排序的行动清单。

# 执行步骤

先明确输入：

- 评估对象：仓库 / app / 落地页 URL / PR 或分支 / 一组截图
- 可选：指标数据（留存、转化、DAU/MAU、收入）、竞品、定价页
- 有就能看则看；没有的证据就标"未评估项"

工作流：

1. **收集证据**：读产品实体（代码 / 界面 / 文案 / 落地页 / 截图）；能跑就跑一遍，实际走关键路径（模拟器 / 浏览器）；有数据就引用（仓库里的、后端的）。此阶段只收集，不评估。
2. **逐视角打分**：每视角 1-5 分 + 一句理由；最强项 1 个 + 关键问题 1-3 个，每个问题按"证据 → 影响 → 建议改法"三段写。
3. **排行动清单**：跨视角合并去重，按 **影响 × 成本** 排序，标注视角来源；前三项标"这个月做"。
4. **出报告**：一张总览表 + 四张视角卡 + 行动清单。决策就绪，不贴原始 dump。

# 判断规则

四个视角逐项核对，每个视角一张独立评估卡：

## 1. 产品 Product

- **定位与价值主张**：一句话说清"为谁解决什么问题"；新手从首页 5 秒内能不能读出这句话
- **问题匹配**：有没有人在真的疼；范围克制吗（MVP 还是大杂烩）
- **差异化**：与替代品相比，凭什么选你
- **一致性**：功能清单与定位是否互相打架；路线是否自洽

## 2. UX

- **上手**：新用户从零到第一次"啊哈"的步数；引导与空状态有没有
- **可用性**：关键路径点击次数、文案清晰度、反馈闭环（每个操作都有可见响应）
- **信息架构**：导航位置能否被猜到；层级是否平
- **感官与可访问性**：动效克制、视觉一致性、对比度/字号/无障碍标签

## 3. 增长 Growth

- **获客**：有没有天然分发钩子（分享、邀请、内容、社交证明）；获客渠道假设可验证吗
- **激活**：新用户首分钟发生什么；激活事件定义清楚吗、埋点存在吗
- **留存**：回访理由（数据回流、任务闭环、习惯养成）；流失点在哪
- **闭环与变现**：单用户价值；有没有"用 → 带人 → 回来用"的闭环；定价进得去退得出吗

## 4. 商业 Business

- **单位经济**：成本结构、毛利；获客成本能覆盖 LTV 吗
- **市场**：TAM/SAM/SOM 量级、竞争格局、护城河（网络效应/数据/品牌/转换成本）
- **风险**：平台依赖（商店政策、API 变更）、合规（隐私、资质）、单一客户
- **GTM**：上线路径、渠道、"为什么是现在"

## 与 erlin-autopilot 的配合

erlin-autopilot 跑完后默认只做标准/规格审查（按 erlin-dev-standards）。想要产品层视角时，对合并结果再跑一次 `erlin-product-review` 技能——erlin-autopilot 回答"做对了没"，erlin-product-review 回答"值得做吗、做得好吗、怎么更好"。

# 输出格式

```markdown
## 总览
| 视角 | 分(1-5) | 一句话 |
|---|---|---|
| 产品 | 3 | 定位清晰，差异化弱 |
| UX   | 4 | 上手顺，首屏文案拖后腿 |
| 增长 | 2 | 没有激活定义，埋点缺失 |
| 商业 | 3 | 单位经济可行，护城河浅 |

## 产品
最强项：…
关键问题：
1. [证据] → [影响] → [建议]

## 行动清单（影响×成本排序，前三项这月做）
1. (增长) 定义激活事件 + 埋点 → 1-2 天
2. (UX) 首屏文案 A/B → 半天
3. …

## 未评估项
（没有证据、不敢下结论的项，标注需要什么证据）
```

# 示例

## 用户问题

"上线前评估一下，这个功能值得做吗？"

## 工具返回

本技能无外部工具调用，以实际输入材料代替：读到的产品实体（代码 / 界面 / 文案 / 落地页 / 截图）、实跑关键路径的观察；可选的留存 / 转化 / 收入数据、竞品、定价页。

## 最终输出

按「输出格式」交付：总览表（四视角 1-5 分 + 一句话）、四张视角卡（最强项 + 关键问题，每条按"证据 → 影响 → 建议"三段）、按影响 × 成本排序的行动清单（前三项标"这个月做"）、未评估项（标注需要什么证据）。

# 门禁

原则：**先摆证据，再下判断**——每个结论都要指出依据（界面行为、数据、代码、市场事实）；分不清证据和观点的地方单独标注"未评估项"，绝不脑补。
