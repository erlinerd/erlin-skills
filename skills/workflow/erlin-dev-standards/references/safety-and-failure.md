# 安全与失败处理规范

本索引承载 `erlin-dev-standards` 的错误处理、敏感数据和破坏性操作规则。

## 1. 失败不得静默吞掉

禁止空 `catch` / `except: pass`，禁止用默认值兜住异常，禁止把错误降级成 warning 后继续。捕获异常必须处理、包装后重抛，或记录并终止，并说明为什么这是可恢复的。

## 2. 敏感数据底线

不把 secret、token、密钥、私钥、生产连接串或个人信息写进代码、测试固件、日志、提交信息或报告输出。不在终端回显或粘贴环境变量内容，只引用变量名。发现仓库已有硬编码凭据时，立即告知，不顺手提交包含它的改动。

## 3. 破坏性操作边界

不可逆操作先确认，理由是回滚成本而不是礼貌：

- 动 Git 历史前先检查 `git status`，识别并避开未提交改动。
- 严禁 `reset --hard`、`push --force`、对已推送分支 rebase，除非用户明确书面要求。
- 未经授权不执行 `commit`、`push`、创建 PR 或改写共享历史。
- 改依赖锁文件、构建/签名配置、数据库迁移定义前先检查目标与回滚方式；已属于明确授权的工程修改不重复确认。实际执行不可逆迁移或扩大权限另需授权。
- 删除或覆盖前先读目标内容；目标与描述不符时停止澄清。已授权代码删改可执行；用户资产清理按 erlin-safe-delete 先确认再移废纸篓；本次自建且确认无用的临时物可自行清理。

## 4. 自治边界

worktree、隔离环境或并行执行都不放宽本节边界——隔离不是沙箱。

**默认可自动执行**（仍受 §1–§3 约束）：

- 读、改文件；编写与运行测试、lint、typecheck、build；
- 安装有正当理由的 dev 依赖；
- 创建分支与 worktree（遵循 Git 工作流规范 §1）；
- 清理本次自建且确认无用的临时物，不涉及用户资产或他人 WIP。

**须用户明确授权**（已有授权不重复询问）：

- commit、push、创建 PR；

- 对保护分支 `push --force` 或改写已推送历史；
- 生产部署；生产数据库破坏性操作；
- 云资源删除；破坏性第三方 API 操作；
- package 发布、App Store 提交、marketplace 发布；
- secret 轮换或暴露；不可逆 migration。

普通 feature 分支的 commit / push / PR 也按已有授权执行，见《Git 工作流与提交规范》§3.5。
