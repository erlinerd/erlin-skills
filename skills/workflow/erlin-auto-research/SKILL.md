erlin-auto-research — 数值指标自动实验循环

# 目标

对"一个能输出单一数字的命令"跑无人值守试错循环：**提假设 → 改 → 门 → 测 → 保留或回滚 → 记账 → 下一轮**。原则：**每个"改善"必须带证据（三次取中位数 + 超过噪声阈值 + 正确性门通过）**；证据不足一律回滚。本技能是纪律层，不绑定项目；参数由调用方提供，缺了先问。也用于给 Goal 模式、Automations 配自主优化长任务。

# 执行步骤

**参数四要素（缺任何一项 → 停下问，最多问一轮，不许自行脑补）**

1. **指标命令**：输出单一数字的 shell 命令（如 `npx vitest run` 取总耗时、`next build` 取产物体积）。
2. **方向**：lower（越小越好）或 higher。
3. **最大轮数**：默认 10。这是配额保险丝，**不接受"无限"**。
4. **正确性门**：证明改动没把事搞坏的命令（全量测试 + lint；项目没有则拒绝启动）。

可选：**目标值**（达到即提前收工）。四要素齐备且用户已给全 → 免复述直接跑；否则向用户复述四要素后开跑。

**启动门（四项全部 PASS 才许开跑，任一 FAIL 先整改或停）**

1. **分支隔离**：git 工作区干净；从基线分支切出 `auto-research/<指标名>`。禁止在 main/develop 直接跑；禁止动实验分支之外的分支。
2. **指标可跑**：指标命令手动跑通并拿到数字。失败即停，不许带病循环。
3. **门可跑**：正确性门命令存在且当前全绿。没有门的仓库不许跑——没有裁决正确性的手段，"改善"不可信。
4. **权限就绪**：本轮免审批已开（每轮要改文件 + 跑命令，弹窗卡死循环）；配额预期已告知（每轮 ≈ 改动 + 门 + 指标三跑的 token 量级）。

**基线协议（噪声闸门）**

指标命令连跑 3 次，取**中位数**为基线 B，记录三次极差。噪声阈值 **N = max(2%, 极差 ÷ 2)**。此后任何"改善"必须满足：门通过 **且** |改善| > N。基准噪声大时这是防"保留运气性回归"的唯一闸门；同一 commit 连跑两次结果差超 N → 判基准不可靠，停并报告，等用户换指标。

**每轮循环（五步顺序固定，不许跳步、不许合并）**

1. **假设**：读当前代码与 EXPERIMENTS.md，提出一个改动假设。**一次只改一处**；禁止捆绑不相关改动（那会让"哪处起效"无法归因）。
2. **实施**：commit，信息格式 `[exp N] <假设一句话>`。
3. **门**：跑正确性门。门不过视同实验失败 → 直接进第 4 步回滚，日志标"门失败"。禁止"测试挂了但指标变好所以保留"。
4. **测**：指标命令连跑 3 次取中位数 M。M 相对 B 改善超 N → **保留**，B 更新为 M；否则 `git revert` 该实验 commit。禁止保留"没变坏也没变好"的改动（每次保留都在稀释归因）。
5. **记账**：EXPERIMENTS.md（仓库根）追加一行：`| # | 假设 | 门 | B→M | 噪声内/改善 | 保留/回滚 | 一句话结论 |`。

**停止条件（四条并列，任一触发即停）**

- 达到目标值（若给了）。
- 用满最大轮数。
- **平台期**：连续 3 轮无有效改善——洼地挖完了，继续烧配额无意义。
- 出现无法自动裁决的分歧（两方案都想保留但互相冲突、或假设需要产品取舍）→ **停下问人**，禁止替用户拍板。

**收尾汇报（固定格式，缺项要说明为什么）**

1. 保留清单：每条含假设、改善幅度（含相对百分比）、commit hash。
2. 回滚计数与失败原因分布（门失败 / 噪声内 / 变差）。
3. 净变化：原始基线 → 最终值。
4. 合并建议：squash 成一个干净 commit 还是保留实验历史；EXPERIMENTS.md 留档，分支去留交用户决定。

# 判断规则

- **适用**：优化可数值化、可反复测量的指标（耗时/体积/压缩率/分数），或在 Goal 模式、Automations 里挂自主优化长任务。
- **不适用**：无数字判据的工作——新功能、UI 设计、正确性重构（"好不好"要人判，循环无法裁决）；这类转 erlin-autopilot。
- **与 erlin-dev-standards 的关系**：那个管"怎么写对"，本技能管"怎么自动试错不跑偏"——证据闭环、失败不静默在循环里逐轮执行。
- 连续 3 次工具级失败（命令挂、revert 冲突）→ 停，暴露最可疑假设，转人工——继承 erlin-dev-standards「按假设排障」的熔断规则。
- 同一 commit 连跑两次结果差超 N → 基准不可靠，停并报告，等用户换指标。

# 输出格式

- 过程台账：EXPERIMENTS.md（仓库根），每轮追加一行 `| # | 假设 | 门 | B→M | 噪声内/改善 | 保留/回滚 | 一句话结论 |`。
- 收尾汇报固定四项（保留清单 / 回滚计数与失败原因分布 / 净变化 / 合并建议），缺项要说明为什么。

# 示例

## 用户问题

"帮我把测试套件跑快一点：`npx vitest run` 现在约 90 秒，自动优化，目标 80 秒以内，最多跑 10 轮。"

## 工具返回

### 指标命令（npx vitest run，三连跑）

基线三跑：92s / 91s / 94s → 中位数 B=91s，极差 3s，N = max(2%, 1.5s) ≈ 1.9s。

### 正确性门（全量测试 + lint）

基线全绿。第 3 轮改动后门挂 2 个用例 → 该轮视同实验失败。

### git

实验 commit `a1b2c3d`，信息 `[exp 3] 缓存 tsconfig 解析结果`；三跑中位 86s，91→86 改善 5s > N → 保留，B 更新为 86s。第 4 轮 `b4c5d6e` 三跑中位 85.5s，改善 0.5s < N → `git revert b4c5d6e`。

## 最终输出

- EXPERIMENTS.md 台账（示例行）：`| 3 | 缓存 tsconfig 解析 | 绿 | 91s→86s | 改善 | 保留 | 构建期缓存命中 |`。
- 收尾汇报：保留清单 4 条（含相对百分比与 commit hash）；回滚 6 次（门失败 2 / 噪声内 3 / 变差 1）；净变化 91s → 80s 达标停；合并建议 squash 成一个干净 commit，EXPERIMENTS.md 留档，分支去留交用户。

# 门禁

红线（触发任何一条 = 立即停并报告，不等轮末）：

- **禁止靠削弱正确性刷指标**：删测试、跳过用例、放宽断言、删功能让数字变好，视同作弊。
- **禁止改考卷**：不许动指标命令本身或其输入数据。
- 禁止 force push、禁止跨分支操作、禁止在 main/develop 直接跑。
- 连续 3 次工具级失败（命令挂、revert 冲突）→ 停，暴露最可疑假设，转人工。

开跑前门禁：参数四要素缺一不跑（不许自行脑补，最大轮数不接受"无限"）；启动门四项全部 PASS 才许开跑；没有正确性门的仓库不许跑。循环中：证据不足一律回滚；禁止"测试挂了但指标变好所以保留"；无法自动裁决的分歧停下问人。
