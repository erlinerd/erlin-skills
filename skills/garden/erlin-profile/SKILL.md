# 目标

Erlin 的个人知识库技能:把用户的习惯、信息、偏好以编号条目存进 `~/.me/`,支持主动录入/查询与被动询问。数据归用户所有,明文 Markdown,随时可手改。

# 执行步骤

## 主动探查(搜寻习惯)

**只读操作,不修改任何数据源。** 产出的是候选清单,写入 `~/.me/` 必须经用户确认——探查不等于录入。

1. **列数据源**(按可靠度排序):
   - `~/.me/` 现有条目(去重基准,已录的不再提)
   - 全局记忆 `~/.zcode/cli/memories/projects/*/memory/`(MEMORY.md 索引 + 各文件正文,重点看 Why / How to apply 里的行为描述)
   - `~/.agents/AGENTS.md`(workspace 指令里的输出风格与行为约定,就是用户习惯的直接声明)
   - `~/.agents/skills/` 技能名清单(技能 = 已沉淀的习惯,反映用户重复劳动的领域)
   - `~/Code/Projects/*` 的 git 历史(commit message 风格、分支行为、提交颗粒度)
   - `~/Code/Projects/` 目录布局(技术栈与项目形态习惯)
2. **提取候选**:重复出现的行为模式 → 一条习惯;每条标注来源(如"来源:git 历史")。过滤敏感信息。
3. **与 `~/.me` 去重**,合并相近条目。
4. **输出候选清单**:`[候选 n](来源:xxx) 内容`,按类别分组,一次最多 5 条,超出分批。
5. **等用户确认**:回"录 n"、"录 2、4"或"全录"才写入;回"都不录"就放弃,不追问。

## 录入

1. 判断类别(习惯 / 信息 / 偏好),读对应文件确认最大编号
2. 检查是否敏感信息(见「门禁 · 安全」),是则拒绝并说明
3. 追加 `- [n+1] <内容>`;内容精炼准确,带上必要的上下文(何时/为何),不塞一次性数据(具体 commit、临时状态)
4. 回复确认:`[习惯 #n] <内容>`

## 查询

1. 读对应文件(未指定类别则读全部)
2. 按条目编号输出:`1. <内容>`;多类别用标题分组,结果清晰准确
3. 支持关键词过滤(逐文件 grep)

## 更新 / 删除

- 更新:改对应编号条目,回复 `[类别 #n] 已更新: <新内容>`
- 删除:仅用户明确要求时,回复 `[类别 #n] 已删除`

# 判断规则

## 触发

**主动:** 用户说"录入/记一下/保存 xx"、"me 里有什么"、"查一下我的习惯/偏好"、`/me`,或给出任意要存进 me 的内容。

**被动(用户明确要求,别漏):** 对话中出现用户未录入的可复用习惯/偏好/事实信息时(完成工作流、纠正我的行为、表达明确偏好),主动询问"要不要录入 xx 到 me?"——一次只问一条,不打断关键工作,被拒就不追问。

**主动探查(搜寻习惯):** 用户说"探查我的习惯""搜寻一下""me 里该记什么"时执行;新会话开始也可主动提议一次(低频,被拒就不提)。流程见「执行步骤 · 主动探查」。

## 录入判断

- 只存跨会话有效的内容,不存对话级临时内容("昨天做了什么"不录,"周末不工作"可录)

# 输出格式

## 数据位置(遵守 XDG 规范)

- 默认根目录 `~/.me/`(点开头隐藏目录,不污染 home 根;若设置了 `$XDG_DATA_HOME`,数据放 `$XDG_DATA_HOME/me/`)
- 分类文件(不存在则初始化,可按需新增类别):
  - `habits.md` — 习惯(重复出现的行为模式)
  - `info.md` — 事实信息(账号、项目、目录、技术栈)
  - `prefs.md` — 偏好(交流语言、风格、工具选择)
- 每文件内条目按 `- [n]` 全局递增编号,追加新条目不重排旧编号;用户手改过则以文件实际编号为准

## 输出

- 按条目编号,清晰准确;一次录入/查询默认最多 5 条,超出问用户是否要全量

# 示例

## 用户问题

"记一下,我周末不工作。"

## 工具返回

本技能无外部工具调用,以实际输入材料代替:用户这句话,加 `~/.me/habits.md` 现有内容(条目已编号到 `- [12]`,无相近条目)。

## 最终输出

1. 判为习惯(重复出现的行为模式),非敏感,跨会话有效
2. 追加到 `habits.md`:`- [13] 周末不工作`
3. 回复确认:`[习惯 #13] 周末不工作`

# 门禁

## 安全(硬性约束)

- **绝不录入**:密钥、token、密码、私钥、API keys、完整凭据
- 内容疑似敏感 → 拒绝并建议:环境变量 / 系统钥匙串 / 密码管理器
- 录入前默念检查:这条内容被任何人读到会出事吗?会 → 不录

## 编辑纪律

- 数据是用户的资产:修改前先读文件,追加用脚本/Edit 而非整体覆写
- 用户手动编辑过文件 → 尊重,一切以文件实际内容为准
