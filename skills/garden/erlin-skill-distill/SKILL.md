# 目标

Erlin 的技能蒸馏方法论:完成一段有价值的工作后,判断它是否值得变成可复用的个人技能,并满足仓库必要元数据与目录校验。

分工：本技能管**何时提炼、怎么提炼、怎么验证**；frontmatter 与目录同步遵循仓库校验；正文只保留完成任务所需的信息，不强制六段模板，不为一次任务创建新技能。

# 执行步骤

1. **从对话历史提取,不凭空编**:工具调用顺序、用户纠正过的地方(这些是最有价值的信号)、输入/输出格式、产物路径。
2. **对照判断标准**(见「判断规则 · 判断标准」):值得才继续;不值得就说明理由,建议放记忆或 AGENTS.md。
3. **写 SKILL.md**:源码落 erlin-skills 仓库 `skills/<bucket>/erlin-<name>/SKILL.md`(bucket 从 workflow/apple/web/garden 选),保留 frontmatter 必填 name/description/keywords；正文按需要写触发、流程、边界与示例，已有六段可沿用，新技能不强制凑齐。优先补现有技能，避免重复。
4. **注册**:erlin-meta「Erlin 技能清单」对应分组加表格行(需要进每会话速查表再加「高频入口」行)+ `tests/skill-catalog.test.ts` 计数改数;该测试还强制 maturity 字段、`agents/openai.yaml` 镜像、`docs/<bucket>/<name>.md`、`.claude-plugin/plugin.json`、FLOW-MAP、bucket README 同步;`pnpm test` 全绿。
5. **测试**:用 2-3 个真实提示走一遍,检查触发是否正常、输出是否贴合。
6. **迭代**:测试发现问题就改,改完重测;过拟合的规则宁可删。仅用户授权时 commit；不自动修改记忆索引。

# 判断规则

## 何时使用

- 用户明确要求"提炼成技能 / 做成 skill / 沉淀一下"——无论是否提到 erlin 前缀
- 同类需求反复出现，流程已在实际任务验证；一次性经验只作为候选，不自动写文件
- 发现自己正在重复做同一件事(搭脚手架、加动效、发布、排查)
- 用户问"哪些适合提炼成 skill"——此时输出**评估**而不是直接写文件

## 判断标准(先评估,别急着写)

**值得提炼（重复需求 + 已验证流程是前提；下列信号辅助判断）:**

- **可执行流程**:有明确的步骤顺序,换个项目还能照着做(如"给 Next 站点加动效")
- **重复劳动**:已经做过 2+ 次同类事情(如"iOS App + 落地页"组合搭过三遍)
- **踩坑教训**:记录复现条件、原因、适用范围和反例；一次故障不能推导成全局 API 禁令
- **有固定产物**:模板、代码片段可放 `assets/`

**不值得(保持记忆/AGENTS.md 即可):**

- **纯信息**:技术栈清单、账号、目录位置 → 记忆
- **偏好**:语言、交流风格 → 记忆
- **行为约定**:提交规范、命名 → AGENTS.md(或轻量记忆)
- 一次性操作,没有复用场景

# 输出格式

- **源码唯一位置**:erlin-skills 仓库 `skills/<bucket>/<name>/SKILL.md`,由 `scripts/link-skills.sh` symlink 进 `~/.agents/skills/`(本机改完即生效)。禁止直接在 `~/.agents/skills/` 手建 erlin-* 目录——不入 git、不被校验、不被调度。
- 不放 `~/.zcode/skills/`:同名会覆盖 `~/.agents` 的安装。
- 命名:`erlin-<kebab-case>`;目录名必须与 frontmatter `name` 一致。
- 可复用代码放 `assets/`,长文档放 `references/`;正文反引号引用的本地路径必须真实存在(人工核对,无自动校验)。
- frontmatter、目录和资源引用满足现有校验；README 的六段示例仅作可选结构，不机械填空。

# 示例

## 用户问题

"这套 framer-motion → motion 迁移加 Reveal 保险丝组件的做法,沉淀一下。"——即使没明说 skill 也触发。

## 工具返回

本技能无外部工具调用,以实际输入材料代替:对话历史中的工具调用顺序、用户纠正过的地方、输入/输出格式、产物路径(Reveal 保险丝组件模板)。

## 最终输出

`erlin-web-motion` 就是这个习惯的产物:

- 起点:framer-motion → motion 迁移 + Reveal 保险丝组件
- 演进:后续实战补了"环境适配"章节(Next 14 / npm / 无 locale 路由),从单项目专属泛化为通用
- 结构:SKILL.md 六段正文;可复用模板位于 `erlin-web-motion/assets/reveal.tsx`，由目标技能维护;已注册进 erlin-meta 清单与高频入口

技能本身也在进化——新实战暴露的差异回填进对应技能,这就是蒸馏循环。

# 门禁

- 对照「判断标准」:值得才写文件;不值得就说明理由,建议放记忆或 AGENTS.md。
- 技能是给未来会话用的:写清楚触发条件和 Why,别让下个会话重新猜。
- 不要在技能里塞只在某一次会话有效的内容(具体 commit hash、一次性数据)。
- 必要元数据与资源引用由仓库现有校验约束，正文按需要组织,本技能不维护副本;发现冲突时改 README 或改本技能的引用关系,不并行维护两份。
- 完成定义：必要目录注册同步、相关现有校验通过，并报告真实提示验证的结果与限制；不要求自动 commit 或记忆索引更新。
