# 目标

<goal>
引导式制作课程，核心纪律是逆向设计：**画像 → 目标 → 评估 → 骨架 → 正文**，评估先于内容。不允许拿到题目直接开写正文——那是内容堆砌的起点。
</goal>

# 执行步骤

<workflow>
1. **定画像与边界**（缺答案先问，不猜）：学员是谁、已会什么（先备）、时长预算、学完的边界（不学什么）、考核方式。用户只给了主题没给这些 → 先给出你的默认假设清单让用户确认，再往下走。
2. **写学习目标**：单课时 3–5 条，全部用 Bloom 可观察动词，句式「学完本课，学员能在<条件>下<行为动词><对象>，达到<标准>」。
   - 合格动词：列出、解释、举例、实现、演示、配置、对比、区分、定位原因、评判、辩护、设计、构建、重构、编写。
   - 禁用（必须行为化改写后才能用）：了解、熟悉、掌握、理解、知道、学会。
   - 改写示例——差：「了解 HTTP 缓存」；好：「给定一个缓存不生效的页面，学员能用 DevTools 定位缓存头问题，并在 10 分钟内修复」。
3. **先写评估，再写内容**：每条目标至少 1 条评估（测验题/动手任务/产出物），写完摆出三方对齐表（目标 × 评估 × 正文小节），出现空格就回去补齐。这一步不允许跳过。
4. **排课时骨架（Gagné 九事件）**：引起注意 → 告知目标 → 激活先备 → 呈现内容 → 学习指导（示例/脚手架）→ 引出练习 → 提供反馈 → 评估表现 → 保持与迁移。骨架先给用户过目，认可后再填正文。
5. **填正文（Mayer + 密度基线，默认值，项目明文标准优先）**：
   - 每站正文 ≥ 1500 汉字；
   - 交互组件不得连排，组件之间必须有正文过渡；
   - 交互后必带操作回顾 + 机制深析；
   - 大段有节奏切分、重点有信号标记、图示与说明相邻、对学员用第二人称。
6. **交付前过评审**：调 erlin-course-review 自审，P0 清零才交付；P1 未清零时逐条列明留给用户决定。
</workflow>

# 判断规则

<rules>
- **润色类请求不降级**：用户说"帮我润色/改写这段课件"时，仍先查目标与评估是否存在且对齐，缺就补齐并向用户说明，不只做文字活。
- **主题先行时先立目标**：用户只给主题不给目标，第一步先产出目标草稿（Bloom 动词）给用户确认，确认后才进入评估设计。
- **项目标准优先**：项目有自己的课程标准（如 courseX 的密度硬标准、词汇表约束）时，以项目标准替换本技能对应默认值，其余流程照走；替换处在产出物里标明。
- **与其他技能的配合**：

  | 技能 | 时机 | 职责 |
  | --- | --- | --- |
  | erlin-course-create（本技能） | 写之前、写的时候 | 逆向设计引导制作 |
  | erlin-course-review | 写完之后 | 严格评审、三档判决 |
  | erlin-dev-standards | 课件含交互代码时 | 代码实现的工程纪律 |
</rules>

# 输出格式

<output-format>
- 交付序列固定：画像假设清单 → 目标草稿 → 评估与对齐表 → Gagné 骨架 → 正文 → 自审报告（erlin-course-review 三档判决）。
- 目标与评估编号统一 `<G1>`…`<Gn>`、`<A1>`…`<An>`；对齐表按「目标 × 评估 × 正文小节」三列，摆不出无空格的表就没做完。
- 占位符统一 ASCII 尖括号（如 `<条件>` `<先备>` `<时长预算>`），不用方括号或全角〈〉；需要用户确认的槽位留空并明示等待确认。
</output-format>

# 门禁

<gates>
- **评估先于正文**：没有评估设计和对齐表，不允许开始写正文。
- **禁用动词必须改写**：目标里出现"了解/熟悉/掌握/理解/知道/学会"原样交付即不合格。
- **交付前 review P0 清零**：没跑 erlin-course-review 就声称"做完了"即违反本技能。
- **三方对齐可检验**：目标、评估、正文小节必须能摆成一张无空格的对齐表；摆不出来就还没做完。
</gates>
