# 目标

把代码库、技术项目或文档集变成一套能照着学的专题：**首页 + 计划页 + 记录页 + N 篇工作纸**。核心是用真实材料建立地图，用可验证能力安排顺序，用记录和验收闭环；不是把目录改写成一篇长介绍。默认在当前项目根目录创建或更新 Markdown 文件；不自动上传外部服务——需要同步飞书时交给 `erlin-feishu-wiki`。

# 执行步骤

1. **确定目标与材料类型**：判断是代码项目、文档集，还是两者混合；定位项目根、文档根、当前版本/commit/日期和可用工具。
2. **收集事实**：代码项目查 `git`、目录和符号；文档集查目录、标题、链接、版本、发布日期和交叉引用。导览中出现的函数、文件、章节和命令必须在材料中真实存在。
3. **落盘到 `.erlin/course/`**：按模板创建 `00-home.md`、`01-plan.md`、`02-record.md`，再从 `03` 开始创建每一篇工作纸。
4. **搭首页地图**：代码项目按包/目录分层；文档集按主题、概念依赖或阅读顺序分组。生命周期只写成引导性骨架，并标注后续篇章验证范围。
5. **写递进路线**：默认约 8 篇，按基础 → 深入 → 实战；每篇写具体入口、关键词、时长和可验证的「读完你能」。文档集没有代码实战时，把第三阶段改成摘要、交叉引用、复述、检索或小型写作产出。
6. **插入「本篇导览」**：每篇都写“这篇带你做什么 / 走读路线（每步标分钟） / 带着读的疑问”，且基于真实材料。
7. **建立证据样板**：记录页的示范日志明确标注“示范格式，非真实学习流水”；生成实际专题时，示范内容中的基线、命令、结果必须来自真实检查。未运行写“待执行”。
8. **选择验证方式**：代码项目用 focused test/typecheck/lint；文档集用 Markdown lint、链接检查、标题/目录一致性、可复现检索或人工交叉引用检查；没有可执行检查时记录“无自动验证入口”，不伪造测试通过。
9. **最终终检**：运行 `node <skill-dir>/assets/check-course.mjs .erlin/course`。它会扫描未替换占位符、必需文件、篇章编号、相对链接和首页/计划/记录映射。终检未通过就保持任务未完成；未创建看板时先删除看板链接占位行。
10. **可选发布**：需要同步飞书时，交给 `erlin-feishu-wiki`；本地 Markdown 终检通过后再上传并远端回查。

# 判断规则

- **真实 > 好看**：真实路径、符号、标题、链接、命令和退出码才算证据；推论单独标注。
- **代表性而非假装穷尽**：明确覆盖范围和未覆盖材料；不要把示例路线写成全库承诺。
- **当前基线与历史分开**：当前 checkout、教材版本和历史文档分别标注；缺失内容如实说明。
- **能力必须可验收**：优先“能说清、能走通、能复述、能定位、能组装、能完成一次检查”，少用“了解/熟悉”。
- **测试按材料类型选择**：没有测试框架的文档集不被强迫伪造 test/typecheck；但必须留下可复现的检查方式或无自动验证说明。
- **Git 归属**：`.erlin/course/` 是默认位置，不等于默认应被 Git 忽略：生成前检查项目现有 `.gitignore` 与团队约定；本技能不静默修改 `.gitignore`。学习计划若属于项目知识资产，保留在 Git 中；若只是个人工作区，再由用户决定是否添加 `.erlin/` 忽略规则。

# 输出格式

默认产物位置 `.erlin/course/`：

```text
.erlin/course/
├── 00-home.md    # 地图：首页分层/目录树或内容地图/生命周期或阅读路径/基线
├── 01-plan.md    # 路线：范围/阶段/篇章/能力卡/验收/时间预算
├── 02-record.md  # 证据：规则/进度/记录模板/学习日志
├── 03-<slug>.md  # 第 01 篇工作纸
├── 04-<slug>.md  # 第 02 篇工作纸
└── ... 10-<slug>.md  # 默认 8 篇时到第 08 篇；N>8 继续编号
```

映射规则：专题页固定为 `00/01/02`；第 N 篇工作纸使用 `(N+2)` 的两位编号，所以 8 篇是 `03`–`10`，不是 `03`–`08`。文件名使用 `0N-<kebab-slug>.md`，保证排序稳定。

产物结构：

1. **首页 `00-home.md`**：代码项目用分层表 + 源码目录树 + 一次调用/消息生命周期；文档集用内容地图 + 文档阅读路径。两者都要有基线、关键概念和下一步入口。
2. **计划页 `01-plan.md`**：基线 → 覆盖政策 → 使用方式 → N 篇按基础/深入/实战分段 → 每篇时长、入口材料和「读完你能」→ 验收目标 → 时间预算 → 相关页面。
3. **记录页 `02-record.md`**：记录规则 → 总进度 → 篇章记录模板 → 横向对照（适用时）→ 一条明确标为示范的日志 → 学习日志。
4. **每篇工作纸**：使用 `assets/chapter.md` 的六区块；若内容需要额外的“阅读任务”区块，明确说明七区块变体。

模板在本技能的 `assets/`：`home.md`、`plan.md`、`record.md`、`chapter.md`；终检器是 `check-course.mjs`。不要依赖另一技能的绝对安装路径。

# 示例

## 用户问题

“帮我把这个代码库安排成学习计划，建个学习库，每篇配工作纸。”

## 工具返回

### git / 目录与符号（收集事实）

代码项目返回当前版本/commit/日期、包分层与目录树素材；导览引用的函数、文件、命令都能定位到真实材料。

### node <skill-dir>/assets/check-course.mjs .erlin/course（终检）

扫描未替换占位符、必需文件、篇章编号、相对链接和首页/计划/记录映射；全部通过才算终检绿。

## 最终输出

`.erlin/course/` 下 `00-home.md`、`01-plan.md`、`02-record.md` 加默认约 8 篇带「本篇导览」的工作纸（`03`–`10`）；记录页含明确标注的示范日志；终检通过。

# 门禁

- 真实证据红线：导览中出现的函数、文件、章节和命令必须在材料中真实存在；推论单独标注；未运行写“待执行”。
- 没有可执行检查时记录“无自动验证入口”，不伪造测试通过。
- 终检未通过就保持任务未完成；未创建看板时先删除看板链接占位行。
- 三页与篇章之间保持同一编号和链接映射；不要用 `...` 代替最终成品中的篇章链接。
- 可选能力（看板、教材补充页、横向对照）没有创建时，删除对应链接和空章节，不留下 `<看板链接>`。
- 记录原始命令输出前先脱敏 token、secret、私钥、个人信息；保留命令、退出码和关键错误即可。
- 不自动上传外部服务；同步飞书必须本地终检通过后再上传并远端回查。
