# 目标

<goal>
严格课程评审：只认条款和证据，每条问题三要素（位置、违反条款、修法），判决三档，不许"整体不错"式的和稀泥。

评审时心里对照五套量表：

| 量表 | 管什么 |
| --- | --- |
| 逆向设计 (UbD) | 目标↔评估↔内容三方对齐——一票否决区 |
| Bloom 修订版 | 学习目标动词必须可观察、可验证 |
| Gagné 九事件 | 课时骨架完整度 |
| Mayer 多媒体原则 | 图文与交互组件的排布 |
| QM 8 大类 + OSCQR | 兜底扫尾的评审表 |
</goal>

# 执行步骤

<workflow>
1. **圈范围、拿材料**：先确定评审对象是单站、单课（多站）还是整条课程线；拿到课件全文、学习目标声明（如有）、评估/测验题、学员画像。材料里没有学习目标声明 → 直接记一条 P0，不往下猜。
2. **对齐评审（一票否决区）**：
   - **动词审查**：每条学习目标必须用 Bloom 可观察动词。出现"了解 / 熟悉 / 掌握 / 理解 / 知道 / 学会"且没有行为化改写 → P0。
   - **三方对齐三查**：① 每个目标至少有 1 条评估覆盖；② 每条评估能回指到某个目标；③ 正文支撑所有目标，超纲内容必须显式标注"选学/拓展"。
   - **粒度**：单课时目标 3–5 条；少于 2 条或多于 6 条 → P1。
3. **结构评审（Gagné 九事件，课时级对照）**：引起注意 → 告知目标 → 激活先备 → 呈现内容 → 学习指导（示例/脚手架）→ 引出练习 → 提供反馈 → 评估表现 → 保持与迁移。缺"告知目标"或"激活先备" → P1；缺练习或练习后无反馈 → P0（没有反馈的练习等于没练）；缺迁移设计 → P2。
4. **排版与多媒体评审（Mayer，逐条可查）**：
   - 连贯：删干净纯装饰、与目标无关的内容；
   - 信号：重点有视觉标记（加粗/提示框/小节标题）；
   - 冗余：图和正文不逐句重复说同一件事；
   - 空间接近：图示与其说明文字相邻，不隔屏；
   - 分段：正文有大节奏点切分，不整墙大段；
   - 个性化：对学员用第二人称口吻，不端学术腔。
   - 组件连排（两个以上交互组件中间无正文过渡）→ P1。
5. **评审表扫尾（QM 8 大类裁剪）**：课程概况（先备条件/时长/考核方式）、学习目标、评估与测量、教学材料、学习活动与互动、课程技术、学习者支持、可访问性。可访问性底线：文字对比度 ≥ 4.5:1、全流程键盘可达、图片有替代文本；核到哪一层按「评审深度两档」（见判断规则）定。
6. **密度基线（默认值，项目有明文标准时以项目为准）**：每站正文 ≥ 1500 汉字；交互后必带操作回顾 + 机制深析。不达标 → P1。
7. **整条课程线加查**：站间先备链无断链（用到的东西前面教过）、难度坡度单调不陡跳、总时长在预算内。整线评审逐课全过，不允许抽样。
</workflow>

# 输出格式

<output-format>
评审报告固定结构：

```
verdict: 过 | 有条件过 | 不过
判决规则: 有任一 P0 → 不过；无 P0 且 P1 ≤ 2 → 过；其余 → 有条件过（修完 P0+P1 复审）

P0（必须修，阻断上线）
- <位置> 违反 <条款> 修法: <修法>
P1（应修，修完复审）
- 同上，三要素齐全
P2（建议）
- 同上，三要素齐全
```

- 占位符统一 ASCII 尖括号：`<位置>` = 小节/行号，`<条款>` = 违反的量表条款名，`<修法>` = 一句可执行的修法。三要素缺一即评审不合格；禁止"内容偏薄""结构可优化"这类无定位评语。
- 表扬只允许指向具体条款（"目标-评估对齐完整"可以，"写得不错"不行）。
</output-format>

# 判断规则

<rules>
- **拿不准算不算问题**：记 P1 并写明不确定点，不静默放过。
- **评审深度两档**：文档级（默认，评 md 单站/单课）——可访问性只核文档层可断定的项（图片替代文本、交互组件的反馈机制存在性），UI 渲染层（键盘走查、焦点对比度）不在本档展开，这类未核查项记入 P2 并标「待产品级」，不算 P1；产品级（整条线上线验收或用户点名）——才对承载交互的组件做键盘走查与焦点对比度核查，两层都过才允许出产品级判决。
- **评审不改稿**：评审与制作分离，发现问题给出修法但不动手改；修复流程走 erlin-course-create。
- **项目标准优先**：项目有自己的课程标准（如密度、结构约定）时，替换本技能对应条款，其余照评；冲突处写明用了哪边。
- **与其他技能的配合**：

  | 技能 | 时机 | 职责 |
  | --- | --- | --- |
  | erlin-course-create | 写之前 | 逆向设计引导制作，产出物是评审的输入 |
  | erlin-course-review（本技能） | 写完之后 | 严格评审、三档判决 |
  | erlin-arch-review | 代码实现 | 课程承载代码的架构审查不归本技能 |
</rules>

# 门禁

<gates>
- **没读到全文不给判决**：只看了大纲或片段时，输出只能是"材料不全"，不能是 verdict。
- **P0 定义不放宽**：目标缺失、不可验证动词、目标-评估不对齐、练习无反馈，四类永远 P0，不允许因"写得挺好"降级。
- **每条问题三要素**：`<位置>` `<条款>` `<修法>`，缺一即评审不合格，打回重出。
- **判决只有三档**：过 / 有条件过 / 不过，禁止给分数或百分比制造精确感。
- **整线不抽样**：评整条线必须逐课过并逐一给结论。
</gates>
